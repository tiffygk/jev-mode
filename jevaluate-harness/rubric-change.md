# Changing the rubric

1. **Capture the ruling:** name what is decided, give a plain-words example and your default, and record the ruling in the rulings log (location per your overlay, or the ledger) the same turn.
2. **Write the rule:** a one-sentence meaning and an invented example for every value, sorted correctly. List the gray areas before writing a new definition and get a ruling on each. Examples must not resemble eval cases; `lint_materials.py` refuses eval-case names.
3. **Split by stakes:** a rule whose test or penalty changes with stakes gets one facts-table row per level (`low`, `high`, `very high`, or a pair such as `high or low`), each saying what a no does there. `step.py` serves only the rows for the levels a project's decisions have; a new label must map in `step.ROW_LEVELS`, which a test checks.
4. **Enforce it:** add or update the rule's row in `jevaluate/enforcement.md`: the function that refuses a wrong answer (`library.py check` or `step.py`), with a test, or "judgment" and why no script can check it. Ask raters only for what they observe; if a value follows from other answers, derive it in `library.py add` instead of asking.
5. **Diagrams:** mermaid, short labels, rendered and looked at before review.
6. **Version:** bump the date in `rubric.md`'s title. A small change adds a point version instead (`2026-09-29.1`): ratings under the same date stay current, since `library.py` compares only the date part. A change is small when it adds or moves an example or a clarifying sentence and changes no allowed value, fact, score anchor or verdict rule.
7. **Test:** run `jevaluate-eval`: the materials check, then the quiz, then the eval. Fix wording only from tuning misses. A small change runs a targeted set instead of the full eval (`run_eval.py --ids`, `run_quiz.py --ids`), on every grader model in use, 3 runs each: every case with a history of being wrong on this rule, controls of the type it must not move, and 5 invented lookalikes the owner labels before any model answers. It passes when the past misses and controls go 3 of 3, the lookalikes 2 of 3, and no control changes type.
8. **Freeze:** after the owner approves and the PR is merged, the owner tags the merge commit `rubric-<version>-frozen` and pushes the tag; agents can't create, move or push these tags. The tag snapshots the whole golden set (`rubric_text.GOLDEN`: the rubric, the rater instructions, `shared/jev-rules.md`, `fix-catalog.md` and the eval keys). Until it exists, `step.py` and `library.py check` refuse to rate, and eval runs score as candidates, not results of record. This step and step 7's tuning-only rule are judgment, recorded in the ledger.
   - **After a point version:** sweep the current ratings for facts the new wording flips, and re-rate only the ratings whose verdict would move (a no that caps the verdict, rubric section 4). A flip that moves no verdict goes on a list for that project's next rating.
9. **Tests on a rubric-change branch:** before the freeze exists, run the suite with `JEVALUATE_TEST_UNFROZEN=1`; it works only with temporary libraries, and the transcript scan flags it in any rater's commands.
10. **Golden files are read-only in the main checkout.** Every change, including a single-word fix to `read.md` or a script, goes on a branch in its own worktree and reaches `main` only through a PR.
