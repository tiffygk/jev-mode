q01

jev-loan-lens is a small loan-approval service. Its README says every application is scored by TypeSafe's Jev before a decision. The code never calls Jev. There is no client, key or network request, only a hardcoded rule: credit score above 640 and income above a fixed figure means approved. The 'jev_score' field in each response is that rule's number renamed. Approvals trigger automatic disbursement through a payments API, so real money moves on the strength of a rule that claims to be an AI model.

q02

tidy-downloads is a command-line tool that cleans a user's Downloads folder. Its README never mentions Jev or TypeSafe. The code sends one yes/no question per file to Jev's HTTP endpoint, such as 'Is this installer older than the software it installs and safe to archive?'. It asks nothing else. Each 'yes' is acted on immediately: the file moves to an Archive folder. A 'no' leaves the file alone. It only touches the user's own files and keeps a log so moves can be undone.

jevkit-js is a client library. The README calls it a 'smart approvals toolkit', which suggests logic of its own. The code is a thin wrapper: it takes questions from other developers' apps, adds an auth header, forwards them unchanged to Jev, and hands Jev's response back untouched. It has no retries that change meaning, no caching, no decision rules and no interpretation of answers. Whatever the calling app asks is what Jev sees. Any action taken on the answer is up to the developer who installed the library.
