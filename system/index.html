Jevaluate System

Jevaluate rates whether open-source projects use TypeSafe's Jev model well. The ratings are public, so every LLM rater has to read the rubric the same way. Code checks every rule a script can check. The rater reports only what it observes, and code derives the rest. An eval with blinded labels tests the rubric before any version is frozen.

DESIGN_RULES

Five design rules

  • Code enforces, text explainsEvery rubric rule has a row in enforcement.md naming the function that refuses a wrong answer, or why the rule stays judgment. A lint fails on a rule with no row or a function that doesn't exist.
  • Ask for what is observedThe rater records type, the call line, each decision with its stakes as read, and the verdict. Code derives kind and every n.a. People and models both miss exception lists. Code doesn't.
  • Evidence over claims"Calls Jev: yes" must cite the file and line of the call, and check confirms it is a call. A README, a docs page or a project name never counts.
  • Stakes change the rowsRules whose test depends on stakes (confidence gating, option order, templated data, untrusted text) get one row per stakes level. The rater sees only the rows its project's decisions need.
  • Refuse, don't warnScripts stop the workflow: a rating over 200k tokens without approval, a missing step log, routing changed after the facts were served, an eval run on uncommitted rubric changes.
1 / HOW THE PIECES FIT

Four skills and one private file

The harness runs three workflows. A rubric change passes the eval before a git tag freezes it. A rating round sends each project to one rater per model and takes their verdict-changing disagreements to the owner. Publishing exports reviewed ratings in one pull request.

jevaluate

Rates one project

Does this project use Jev well?

The rater follows SKILL.md and read.md. A rating costs about 100-300k tokens, by repo size.

jevaluate-private

Rates one project, never published

Does my private code use Jev well?

Same rubric and checks, run with /jevaluate-private. The rating stays in a private library that export refuses.

jevaluate-eval

Tests the rubric

Do graders apply the rubric correctly?

Materials check, quiz, judgment eval, and rater agreement for a second rater. Proposes wording fixes. Never edits the rubric or a rating.

jevaluate-harness

Runs the process

How do I run a round, change the rubric or publish?

harness_status.py reruns the materials lint and the release check and names the next step.

overlay (private)

The owner's own rules

Which extra gates apply here?

Private gates and presentation rules. The public skills stay generic.

3 / EVALUATION

The eval that gates every rubric version

A rubric change runs the first three instruments in order, each passing before the next. The fourth checks a second rater. Pass bars are set before the run, and reports go per rule, never as an average.

  1. 1

    Materials check

    Is what the grader reads consistent?

    1. lint_materials.pyAllowed values agree across files. No eval-case names in rubric examples. Every rule has an enforcement row.
    2. Fresh reviewerBriefed as a grader, reads the materials cold.
    3. Grader viewThe owner reviews exactly what a grader receives, step by step, after any change that moves instructions into code.
  2. 2

    Comprehension quiz

    Does a grader understand the rules on invented projects?

    1. blind writerInvented projectsFrom a model that never saw the rubric, plus five lookalikes written for a rubric change. Some mislead on the surface. Any overlap with rubric wording is rewritten.
    2. Owner's key, 16 projectsAnswered first, observable fields only. A script derives the rest and refuses contradictory answers.
    3. 8 tuning, 8 held outThree drawn at random (seed 29) after the key was final, plus the five lookalikes. Two of those no longer count as held out on stakes: their key changed after a run.

  3. 3

    Judgment eval

    Does a grader route real projects the way the owner does?

    1. Golden dataset19 real open-source projects, keyed. 6 of them cover the gaps: one claims Jev and never calls it, one is an honest stub named after Jev, two are high stakes, two very high.
    2. pick_files.pyFixed file ruleRoot README, every file with a hosted call, then Jev or decision hits up to 4 files. Code before docs and tests, data last. 3,000 characters each.
    3. Provable labelsEvery gold answer must be backed by the packet the grader sees. 13 checked: 12 provable, 1 weak, 0 changed.
    4. blind labelersLabel provenanceNew cases: labels sealed until the owner answers from evidence cards. check_labels.py refuses a label that cites a doc as a call; build_cards.py refuses any verdict word on a card.

    Graders under test: Claude Sonnet and GPT-6 Sol in Codex, on identical inputs.

    The call detector is tested too. Screening about 110 real repos found 4 misses (an AI SDK provider, an Effect provider, Apps Script and Swift files) and 1 false positive (a helper named typesafe_...). Each is now a regression test.

  4. 4

    Rater agreement

    Do two raters agree, and is either right?

    1. Tuning sample named firstProjects whose disagreements fed wording are reported apart, and second.
    2. rater_agreement.pyRaw agreement and Cohen's kappa per field, held-out projects first.
    3. blind ownerAnswer keyA seeded draw of agreed and split facts. The owner answers before seeing either rater.
    4. Consistency onlyAgreement shows the raters read alike. Only the key shows which is right.
  5. FOR STAGES 2-3

    Reproducibility

    Can a score be traced to the exact rubric and key?

    1. run_eval.pyPre-flight refuses uncommitted rubric changes or a branch behind main.
    2. StampEvery quiz and eval run records the commit. Eval runs also fingerprint the answer key.
    3. score.pyRefuses to score if the key changed after the run.
  6. FOR STAGES 2-3

    Report

    What does the rubric get wrong?

    1. Per ruleEach rule tag scored alone. An average hides the rule that fails.
    2. One fix per missed ruleWording fixes come only from tuning misses and never name a held-out case.
    3. StopThe owner sees each fix as a before-and-after. The eval never edits the rubric.
4 / BLINDING

Who is blind to what

Each blind closes one path for leakage, contamination or anchoring. Two roles can't be blind, so rules fence in what each can touch.

WhoBlind toWhyTerm
Scenario writerThe rubric and the answer keysScenarios that echo rubric wording test string matching, not understanding.leakage
The owner, setting the keyEvery model answer and the controller's reading, until the key is setGolden labels can't anchor on a model.anchoring
The owner, ruling on a disagreementWhich rater gave which answer: two answers, A and B, in seeded order, with the rule and the codeA ruling can't lean toward one model.anchoring
Blind labelersThe rubric's accept lists and each other's labels. Labels stay sealed until the owner answers.An independent second opinion that can't touch the key.label provenance
Graders under testThe answer key, eval-case names (a lint keeps them out of rubric examples), the held-out set during tuningA grader that has seen the answers is scored on memory.contaminationoverfitting
Raters in a roundThe rubric past the current phase, and the project's previous rating until its facts and scores are writtenStops skimming ahead and keeps facts and scores from leaning toward an old rating. The verdict comes after, so it can still lean.anchoring
Reviewer of a big verdict moveThe scores and verdicts: it gets only the factsIt judges the move from the evidence, not from either number.anchoring
Final gate reviewerAny summary of the workJudges the artifact, not the story told about it.anchoring
Eval controllerNothing: it knows the keyIt runs the eval. It may fix wording only from tuning misses, draws the held-out set after wording is final, and names any held-out item that fed wording (q09).not blind
